Ways to work together

Pick the model that fits the size of the project. We confirm it in the proposal.

Fixed-scope project

A defined feature set with an agreed timeline and price, written down before work begins.

Best for: a clear product or a well-defined module.

Milestone-based build

A larger product split into stages. Each milestone is delivered, reviewed and approved before the next starts.

Best for: bigger applications that grow in phases.

Ongoing development

Regular monthly hours for new features, fixes and maintenance on a product that is already live.

Best for: products that change continuously.

How I deliver

The practices behind every project, so the result is safe to depend on.

Clear scope and communication

Features, timeline and responsibilities are written down first. You get regular progress updates and a working version to review at each milestone.

Secure by default

Input validation, proper authentication, and secrets kept out of the code. Security is planned from the start, not added at the end.

Maintainable code

Readable structure, version control on GitHub, and a README so another developer can pick up the work.

Tested before launch

Key user flows are checked on real devices and browsers before anything goes live, and handover notes explain how to run and deploy it.

Project process

Five stages, each with a clear output.

  1. Discovery

    We cover goals, users and constraints. Output: a written scope.

  2. Planning

    Screens, data model, API and timeline. Output: a proposal to approve.

  3. Build

    Interface, API and database, developed in milestones you can review.

  4. Testing

    Key flows tested and issues fixed before release.

  5. Launch and handover

    Deployment, code access and setup notes. Support terms agreed.

Questions clients ask

What do you need to give me a proposal?

A short description of the product, who will use it, your deadline and a budget range. If you have examples of similar apps, send them. I'll reply with questions or a proposal.

How long does a project take?

It depends on the scope. I give a timeline in the proposal, broken into milestones, after I understand what you need.

Who owns the code?

Ownership, access and handover terms are agreed in writing before work starts.

Can you work with my existing team or designer?

Yes. I can build from your designs or work alongside your developers, and I use GitHub so changes are easy to review.

How do you handle data and accuracy with AI features?

I plan with you what data goes to the AI provider, keep API keys on the server, and agree in writing what is stored. AI can give wrong answers, so I design limits into the feature and a handover to a person where it matters.

Do you provide support after launch?

Yes. Support and maintenance terms are agreed during planning, either as a fixed period or as ongoing monthly hours.
